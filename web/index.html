Method & limits

A reproducible reimplementation — with the limits stated plainly.

SENTRY is a final-year research prototype built around arXiv:2610.24468. It reproduces the paper's streaming framing, feature families and four-level LOG / CHALLENGE / DROP / UNKNOWN policy on a CPU. It does not claim the paper's FPGA numbers.

0.9999AUC

Pipeline

16 kHz mono in, one action out, every 250 ms.

6 stages
  1. 01
    Ingest

    16 kHz mono, DC removal and pre-emphasis.

  2. 02
    Window

    1 s windows with a 0.25 s hop, four scores per second.

  3. 03
    Describe

    MFCC + deltas, spectral shape, wavelet packets, Walsh–Hadamard, waveform micro-stats.

  4. 04
    Classify

    178-d vector into a LightGBM gradient-boosted tree ensemble.

  5. 05
    Smooth

    Median + EMA with two-window hysteresis so the verdict does not flicker.

  6. 06
    Act

    LOG below 0.40, CHALLENGE between 0.40 and 0.60, DROP above 0.60.

Clip-level aggregation

A fake clip only needs some windows to expose the artefact, so the file and attack tabs do not average every window:

  • clip score = mean of the top 30% of windows
  • AI-window ratio = fraction of windows ≥ 0.60
  • DROP if clip score ≥ 0.50 and ratio ≥ 15%
  • CHALLENGE if clip score ≥ 0.40 or ratio ≥ 5%
  • CHALLENGE if clip score ≥ 0.20 (gray zone); LOG only below that

The sparse-evidence guard escalates LOG to CHALLENGE when the top-10% score is at least 0.45 but the clip score is still below 0.50. That catches long, noisy or music-backed clips where only a few windows expose the artefact. Held-out real FoR clips max out at 0.212 on this statistic, so the guard keeps 0/80 false positives. It fixes Sonia, whose windows are bimodal: about 35% score 1.0 while the plain mean is only 0.44.

What is real vs. reproduced
  • Reproduced in spirit: feature families, streaming windowing, four-level action, CPU-only budget.
  • Not reproduced: the paper's exact integer lifting-wavelet front end, Mahalanobis OOD track and its 98.75% / 1.25% EER numbers.
  • Our extension: augmentation with 2026-era neural TTS, a live attack-lab interface, a measured channel-robustness study (speaker → room → mic), and a nearest-neighbour novelty guard that returns UNKNOWN rather than LOG for unfamiliar audio.
  • Measured: 99.7% accuracy, AUC 0.9999, EER 0.24% on a grouped held-out split (n = 9,908); 96.7–100% on unseen TTS voices.
  • Negative result: modern TTS it has never seen drops to 60.0%, and the microphone channel to 42.0%. A channel-trained specialist overfits speaker identity (34.2% leave-one-clip-out).
Limitations — say these in the viva
  1. FoR is 2019-era; modern zero-shot clones (ElevenLabs-class) are harder.
  2. 1 s windows limit low-frequency cues; long-form prosody is ignored.
  3. Compression, noise and reverb shift the score; calibrate per channel.
  4. This is a decision aid, not forensic proof. Never accuse a person from one score.
  5. Trained on English; Indian-language TTS is out of distribution.
  6. Long, music-backed in-the-wild reels may expose only a few synthetic windows; the sparse guard flags them as unresolved, not clean.
  7. Audio far from the training distribution returns UNKNOWN, not authentic. The novelty guard is a safety net, not a guarantee.
